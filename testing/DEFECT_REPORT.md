## DEF-001 - Anonymous POST /api/v1/agencies/seed-defaults writes to the database

- **Severity / priority:** High / High
- **Area:** Security / API
- **Found by:** New SecurityTests (SEC-08)
- **Status:** Fixed and retested
- **Description:** The endpoint was marked [AllowAnonymous]. Any unauthenticated caller could insert demo carrier agencies into a production database, polluting the agency list the AI matching pipeline chooses from.
- **Steps to reproduce:** 1. Start the API. 2. `curl -X POST http://localhost:5159/api/v1/agencies/seed-defaults` with no Authorization header. 3. Observe HTTP 200 and seeded agencies.

- **Evidence after fix:** `evidence/defects/security-tests-AFTER-fix.log`

- **Retest result:** SeedEndpoints_Return401_ForAnonymousCaller, SeedEndpoints_Return403_ForShipper and SeedDefaultAgencies_Succeeds_ForAdmin all pass (before: 8 of 47 SecurityTests failed, after: 0 of 47).
- **Retest tests (verified passed in the register):** `SecurityTests.SeedEndpoints_Return401_ForAnonymousCaller`, `SecurityTests.SeedEndpoints_Return403_ForShipper`, `SecurityTests.SeedDefaultAgencies_Succeeds_ForAdmin`

## DEF-004 - API crashes on startup against real PostgreSQL when no Admin exists

- **Severity / priority:** Medium / High
- **Area:** Database / Startup
- **Found by:** New Postgres end-to-end workflow test (area E) on Testcontainers PostgreSQL
- **Status:** Fixed and retested
- **Description:** SeedDefaultPricingConfigIfNotExistsAsync used a random Guid as SetByUserId when no Admin user existed. EF Core's InMemory provider ignores foreign keys, so the 560+ existing tests never noticed; on PostgreSQL the insert violates FK_FuelPriceRates_Users_SetByUserId (23503) and the host fails to start.
- **Steps to reproduce:** 1. Start the API (Development) against an empty PostgreSQL with ADMIN_USER_EMAIL / ADMIN_USER_PASSWORD unset. 2. Startup throws DbUpdateException 23503.
- **Evidence before fix:** `evidence/defects/DEF-004-BEFORE-fix.log`
- **Evidence after fix:** `evidence/defects/DEF-004-AFTER-fix.log`
- **Fix:** Seed is skipped (with a warning) when no Admin exists; the next start after an Admin exists seeds the defaults. Commit message references DEF-004.
- **Retest result:** Before: 5 of 7 targeted tests failed. After: 7 of 7 pass, including 3 new unit tests (no-admin, with-admin, idempotent) and the 4 Postgres E2E tests.
- **Retest tests (verified passed in the register):** `SeedDefaultPricingConfig_WithNoAdminUser_SeedsNothing`, `SeedDefaultPricingConfig_WithAdminUser_SeedsDefaultsAttributedToAdmin`, `SeedDefaultPricingConfig_CalledTwice_IsIdempotent`, `FullWorkflow_ShipperPosts_AgentsRun_ShipperApproves_AgencyAccepts_TripPersistedInPostgres`

## DEF-005 - File endpoints return HTTP 500 when Cloudinary is not configured

- **Severity / priority:** Low / Low
- **Area:** Security scan / Robustness
- **Found by:** OWASP ZAP API scan
- **Status:** Open (not fixed)
- **Description:** OWASP ZAP reported 10 HTTP 500 responses (and 'Application Error Disclosure') on /api/v1/files/*. With no Cloudinary credentials the singleton Cloudinary client fails to build and every call becomes a generic 500. The response body is the standard error envelope (no stack trace), and .env.example already documents that uploads require Cloudinary, so this is a configuration-dependent robustness issue rather than a data exposure.
- **Steps to reproduce:** 1. Run the API without CLOUDINARY_* settings. 2. GET /api/v1/files/content/x or POST /api/v1/files/single with a valid token. 3. Observe HTTP 500.
- **Evidence before fix:** `evidence/zap/before-fix/zap-report.html`
- **Evidence after fix:** `evidence/zap/zap-report.html`
- **Fix:** Recommended: validate Cloudinary options at startup or return 503 from CloudinaryFileStorageService when unconfigured. Not changed: out of scope for the testing work and needs a team decision on fail-fast vs. 503.
- **Retest result:** Retest scan still reports the 10 x 500 alert (expected for an open defect). Production deployments set the Cloudinary variables.
